# Den — setup

Encrypted pixel messenger. iOS + Android via Flutter, with a real-time room server and zero-knowledge message relay.

## Stack

| Part           | Tech                                          |
|----------------|-----------------------------------------------|
| Mobile         | Flutter + Flame (isometric pixel renderer)    |
| Room server    | Node + uWebSockets.js (live avatar state)     |
| API server     | Node + Fastify (auth, profiles, key bundles)  |
| Storage        | PostgreSQL + Redis                            |
| Encryption     | Signal Protocol — X3DH + Double Ratchet       |

Server never sees plaintext messages — `messages.encrypted_payload` is an opaque ciphertext envelope produced on-device.

## 1. Prereqs

- **Flutter SDK** 3.16+ — https://docs.flutter.dev/get-started/install/windows
  ```powershell
  winget install --id Flutter.Flutter
  flutter doctor
  ```
- **Node.js 20+** (already installed)
- **Docker Desktop** — for PostgreSQL + Redis
- **Android Studio** (Android SDK + emulator) and/or **Xcode** (iOS, macOS only)

## 2. Boot the backend

```powershell
cd C:\projects\den
docker compose up -d postgres redis

cd server-api
npm install
$env:DATABASE_URL = "postgres://den:den_dev@localhost:5432/den"
$env:JWT_SECRET = "dev_secret_change_me"
npm run dev          # → http://localhost:3001

# new terminal
cd C:\projects\den\server-rooms
npm install
$env:REDIS_URL = "redis://localhost:6379"
$env:JWT_SECRET = "dev_secret_change_me"
npm run dev          # → ws://localhost:3002/room
```

> **Windows note:** `uWebSockets.js` ships pre-built native binaries for Windows x64. If `npm install` fails, fall back to `ws` — swap the import in `server-rooms/src/index.ts` and the API surface is almost identical.

## 3. Boot the mobile app

The platform folders (android/, ios/) are generated by Flutter CLI, not checked in:

```powershell
cd C:\projects\den\mobile
flutter create . --org com.den.app --project-name den --platforms=android,ios
flutter pub get
flutter run         # picks attached device / running emulator
```

The Flame isometric room renders immediately with two demo avatars (you + a friend) in a 10×8 room.

## 5. Architecture notes

**Why uWS for rooms, Fastify for the API?** Two different workloads. Fastify handles request/response with a database; uWS handles thousands of persistent WebSocket connections with minimal overhead. They scale on different axes.

**Why a single Redis pub/sub channel per room?** Lets us scale `server-rooms` horizontally — a move packet hitting any instance is rebroadcast to every instance hosting a peer in that room.

**Why no end-to-end on the room state itself?** Avatar positions aren't sensitive. Encrypting only the chat payload keeps the server simple while still giving Signal-level privacy on actual conversations.
